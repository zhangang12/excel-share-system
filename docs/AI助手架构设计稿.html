AI 助手 L3 · 架构与实施方案

2026-08-01 · 待评审 · 目标：从「查数机器」升级为「会判断、能提案、由人确认执行」的助手

一、能力分级与目标

级别能力说明状态
L1单域问数问什么答什么，7 个只读工具现状
L2跨域串联 + 主动推送一个问题串多域；每日晨报定时送达，不用人问规划
L3判断 · 提案 · 卡片确认识别异常 → 给出结论与依据 → 生成审批卡片，人点确认后由人的身份执行本方案目标
L4自主执行助手直接改数据不做
L3 的关键设计：卡片只是「呈现权」，不是「执行权」 卡片渲染在用户自己的会话里，按钮点下去是用户自己的 token 打现有业务端点。所以审计记的是本人、职责分离照常生效、AGENTS.md 的「工具永远只读 SELECT」铁律保持不变——助手产出的是卡片描述，不是数据库写入。
省掉的东西：agent-bot 服务账号、新的写路径、助手侧的幂等键与回滚设计。

2.1 核心原则（三条，其余都是推论）

原则含义违反后的失效模式
① 单一访问路径工具不写 SQL，只调现有 router 函数并传真实 current；权限与行级过滤自动继承权限双写 → 页面改了规则工具不跟 → 静默越权（已发生）
② 事实源在服务端模型只能决定「把哪件事推到你面前」，不能是「你正在批的是什么」的来源。卡片只携带对象 ID，要素由后端重查回填模型看错或被注入 → 卡上写 ¥4,800、按钮批 ¥48,000
③ 能力可枚举卡片类型是白名单，端点由类型在可信前端代码里决定，不出现在模型输出里模型输出 HTML → XSS；模型指定端点 → 越权调用面无边界

三、安全红线（代码保证，不写进提示词）

提示词可以被绕过，白名单不行。以下每条都在 guard.py 出口统一强制。
红线理由
表黑名单：app_settings、agent_chat_logs前者存着助手自己的 API Key 明文，读到即随回答外泄；后者存着所有人问过的问答，能读自己的日志 = 一次性绕过全部行级隔离
字段黑名单：password_hash、employees.id_card、suppliers.bank_account、employee_salary_monthly.*身份证号现在 _emp_out() 原样返回；供应商银行账号是付款诈骗的直接素材
JSON 自由列不返回原始内容：records.values、projects.extra、custom_values、oa_requests.detail字段级权限只对 fields/overview_fields 生效，对这些列完全无保护，里面可能藏报价、成本、私人备注
返回行数上限 20系统有独立的导出审批闸门（export_requests），AI 一次吐 200 行等于绕过
门控只做菜单级hidden_tabs（二级 tab）只在前端隐藏、后端零处强制，不可当作可信边界
成本类回答带口径声明采购用 project_code 字符串软关联挂项目（无外键），成本汇总会静默漏数
卡片第一期不开批量卡片让「一次批 20 条」变容易，效率是真的，风险倍数也是真的

P5L3工具扩面：按 gap-analysis Quick Wins 6 个（低库存 / 待开票待付款 / 待发货 / 已开票未付款 / 在职人数 / 我的待办审批）3–4 天覆盖域从 5 张表扩到 15+，每个新工具走 P1 模板

P0 与 P1 之间没有依赖，但 P0 必须先做——它跟架构选哪条路无关，是正在发生的暴露。

为什么第一张卡片是「请款审批」

  • 驳回流程刚上线（2026-08-01），链路最新、最熟
  • approve 端点已带职责分离校验，正好验证「复用端点谓词」这条设计
  • 「收款账号本周刚改过」这个标记，直接对着付款诈骗最典型的手法
  • 杨坛既是真实审批人，也是提反馈的人，反馈闭环最短

五、实施技术框架

层选型说明 / 理由
Agent 形态单 Agent + 工具循环不做多 Agent——只会放大权限与成本问题。保留现有 4 轮上限，补全局 deadline（现在 30s 是每请求的，4 轮无总超时）
LLM 接入保留厂商中立层待你确认判据只有一条：未来一年是否可能换供应商 / 接内网私有模型。会 → 留；基本锁定一家 → 这层是白付的税，换官方 SDK 可拿到缓存精细控制与结构化输出保证
工具定义装饰器注册 + 自动生成 schema替代现在「后端 schema/labels/suggestions/run_tool + 前端 labels」六处手工同步
数据访问复用 router 函数不做 Text-to-SQL：7 类行级规则 + 字段级权限 + JSON 自由列，这套权限模型套不进生成式 SQL；且 records.values 是 EAV 无业务语义
语义层复用 reports_router资金面板 / 13 周现金流 / 项目毛利榜的口径已在代码里定死且含防双算逻辑（毛利两腿互斥、现金排程剔重），重写 SQL 极易错
检索不引入 RAG / 向量库这是结构化数据问答，真需求是「查数准确」不是「找相关段落」
输出通道SSE 流式 + 卡片块现在是非流式三点动画；L3 单轮会更长，流式是体验刚需
卡片渲染受控 schema + 可信组件绝不让模型产出 HTML——现前端 XSS 防线是 markdown-it {html:false}，模型一旦输出标签这道防线就没了
成本控制prompt 前缀重排 + token 记账现 system prompt 第一句就插用户名和角色 → 跨用户前缀零共享。规则段是最长部分，挪到最前即可进共享前缀
会话后端持久化现历史存前端内存、刷新即丢；且截断纯按条数(20)×字符(2000)，最坏单轮 30–50k token 无上限保护
审计扩 agent_chat_logs补 token 用量 / 成本 / 工具入参 / 轮次 / 卡片动作（哪张卡、谁点的、结果）
