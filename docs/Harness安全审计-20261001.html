Harness 安全审计

老板拍板「Harness 直接当生产运行时」。本报告审它能不能上、怎么上：默认配置下有哪些风险，部署时必须做哪些加固，怎么接进现有系统。

00结论

5严重
7高
10中
5低

默认配置不能上生产；按第 05 节加固后可以作为运行时。前提是安全边界放在 ERP 这一侧，而不是 Harness 里。

  • 它是为「一个开发者在自己电脑上用」设计的：没有多用户概念；默认就开着命令行、读写文件、上网、跑脚本这一整套能力；工具调用默认直接执行，不做审批；沙箱只管写文件，不隔离网络。官方安全说明也写明它「尚未接受安全审计，不得视为安全或可用于生产环境的软件」。
  • 默认还会把数据带出去：每次调用模型都会额外上传整段会话日志（含工具查到的业务数据，每次最多 8MB）；用户点反馈会把整段会话传到 DeepSeek 的遥测服务器；模型能把数据发到任意公网地址。
  • 好在这些都关得掉：它「一切皆插件」，上面的能力都是独立插件，可以逐个禁用；我们要用的运行模式不监听任何端口；工具执行流水线里有一个「只能拒绝、不能被改成允许」的守卫挂点，适合挂我们的白名单和审批。
  • 适配思路：Harness 管思考，ERP 管动手和刹车。Harness 只保留和 ERP 通信的那一个通道；身份、权限、演练、审批、打码、限额全部在 ERP 后端强制执行。就算 Harness 被提示注入攻破，没有 ERP 签发的审批记录，写操作也执行不了。

01范围与方法

  • 对象：官方仓库 master 分支 639ed015（2026-09-29），版本 0.2.0-rc.2，61 个模块。
  • 方法：只读源码，不安装、不运行（它的安全说明要求在一次性环境里运行，审计不需要）。分 4 个方向并行审：网络暴露与身份隔离；工具执行、沙箱与审批；数据外发、凭据与供应链；MCP、提示注入与前端。另把锁文件里 1,684 个第三方包版本拿去和公开漏洞库 OSV 比对。
  • 核实：下表标「已核实」的条目，我逐条打开源码原文对过；其余条目来自审计子任务给出的文件和行号，未逐行复核。
  • 部署假设：独立容器；每个活跃用户一个 Harness 进程，同时最多 2 个；只接 ERP 的 MCP 工具；模型用 DeepSeek API。

03做得好的地方

  • 我们要用的运行模式（sdk、acp、headless）都不监听端口，没有对外入口。
  • 工具执行流水线有「守卫」挂点：只能拒绝、不能被其他规则改成允许，子 Agent 和代码执行发出的调用也覆盖得到，适合挂白名单。
  • 会话 ID 会转义，运行模式名有校验，存储键有安全检查，没发现路径穿越。
  • 凭据文件权限是 0600；如果组或其他用户可读，会拒绝启动。
  • 网页版的防 DNS 重绑定、CSRF 设计是合理的（Host 白名单、校验来源、SameSite=Strict）。
  • 模型输出里的原始 HTML 按纯文本显示，链接只允许 http、https、mailto；附件文件名有清洗，没有命令注入。
  • 依赖安装默认拒绝执行安装脚本；Python 运行时打包的二进制都有 SHA256 锁定。

04依赖漏洞

锁文件里 1,684 个第三方包版本中，29 个在公开漏洞库里有记录。按运行时是否用得到分开看：

包最高级别谁在用对我们的影响
undici（网络请求）高：TLS 证书校验可被绕过等只被构建工具引用（下载 Electron、打包、测试、编译原生模块）运行时用的是 Node 自带的网络库，不受影响；保持 Node 22 最新补丁

js-yaml高：恶意 YAML 可耗尽 CPU读配置文件配置文件由我们提供且只读，影响低；构建时升级
extract-zip高：借符号链接任意写文件，无修复版运行时没有找到引用它的包禁用插件管理后不涉及

05部署加固清单（上线前逐项过）

  1. 运行方式：用 acp 或 sdk 模式，经标准输入输出驱动，不起任何网页服务。用户与进程一对一，同时最多 2 个（信号量），空闲 15 分钟回收，单轮设超时。对话历史存在我们后端，新会话带摘要续接。禁止使用 sdk-minimal。
  2. 禁用插件（以配置补丁加载）：命令行与文件（tool-bash、tool-pwsh、bash-sandbox、shell-env、tool-fs、tool-fs-search）；上网（tool-web、web、web-search-deepseek、web-fetch-http）；子 Agent（tool-subagent 全系、subagent-spawn-in-process、subagent-fork-in-process）；脚本与自动续跑（ptc-runtime、workflow-ptc、tool-workflow、goal 全系、tool-jobs、plan-mode）；技能与办公组件（tool-skill、skill、skill-filesystem、skill-office、workspace-dependencies）；数据外发（session-log-deepseek、session-telemetry-otel、command-feedback、plugin-package-inventory-deepseek、llm-pi-ai、deepseek-account、llm-deepseek-account）；管理面（plugin-manager、config-editor、settings、agent-instructions）。
  3. 只插入两个插件：erp-mcp（streamable-http，https，请求头 Authorization: Bearer ${ERP_MCP_TOKEN}，启动连不上就失败）；erp-gate（自建）：① 守卫白名单，只允许 mcp__erp__*；② 写工具一律发起审批，审批理由里带工具名和参数；③ 审批应答器把请求转给我们后端，自设超时，记录放行的调用编号。
  4. 环境：用 env -i 包装启动，只传 DSH_HOME（每用户独立目录，0700，模型不可写）、DEEPSEEK_BASE_URL（指向我们后端的模型网关，见 F 项）、网关签发的调用凭据、ERP_MCP_TOKEN（每用户一个）、DSH_TELEMETRY_DISABLED=1、DSH_TELEMETRY_MODE=DISABLED、DSH_PERMISSION_MODE=read-only、DSH_TOOLS_MODE=native、NO_PROXY。启动目录用空目录。配置补丁只读挂载。
  5. 容器：独立容器，不发布端口；网络层出站只放行我们自己的后端（MCP 服务和模型网关），不出公网；非 root 运行；根文件系统只读，只有 DSH_HOME 卷可写；启用 --init；设内存上限；umask 077；容器里不放数据库连接串，不挂业务数据卷。
  6. 模型网关：Harness 不直连 DeepSeek，所有模型请求经我们后端转发。网关做三件事：① 逐次记 token 和费用，到月度上限（暂定 1000 元）自动停用；② 只转发推理必需的字段，剥掉会话日志、插件清单、用户 ID 请求头等附加内容（即使 B 项哪一项没关住，这里也会被剥掉）；③ DeepSeek 的 API Key 只存在后端，Harness 容器里没有。
  7. 数据：Harness 的会话落盘和临时溢出文件定期清理（建议 7 天）；正式记录以我们后端的审计为准。银行账号、身份证、工资薪酬、手机号在 ERP MCP 服务端打码后再给模型；模型拿到的是代号，执行时由服务端换回真值。
  8. 构建：把仓库 fork 到我们自己的仓库，固定 commit；用依赖覆盖强制升级第 04 节的包；锁文件安装；镜像构建完再扫一次漏洞。升级 Harness 版本必须先过业务评测、越权回放和本清单自检。
  9. 启动自检：每个进程启动后导出生效配置，确认上面的禁用项都没有加载；会话开始时核对工具清单只有 mcp__erp__*。任何一项不符就不接流量。
  10. ERP 侧兜底（最重要）：MCP 服务按令牌识别用户，以本人身份调原业务接口；写操作必须有后端签发的审批记录（调用编号 + 参数哈希）才执行，没有就拒绝，不管 Harness 那边说什么；演练、打码、限额、审计全在 ERP。MCP 服务不返回说明文字、不发跳转、固定工具清单、限制返回大小、校验资源 URI。

Harness 那一侧的审批是第一道；ERP MCP 服务核对审批记录是第二道，也是真正的保证：就算 erp-gate 没加载、被绕过，没有后端签发的审批记录，写操作照样执行不了。

07前端复用

Harness 的前端是 React 18（我们是 Vue 3），真正的界面代码在 63 个包里，约 16.7 万行，由插件动态拼装。它本质是带终端和插件安装的单人控制台，安全边界不适合直接给 27 个业务用户。

08第一周实测项（审计里标「未确认」的）

  • 禁用上面那些插件后能否正常启动（插件之间的依赖关系）。
  • 每个 Harness 进程实际占多少内存，2 核 3.5G 跑 2 个并发够不够。
  • erp-gate 插件加载失败时，进程是拒绝启动还是照常运行（后者就全靠启动自检和 ERP 侧兜底）。
  • acp 模式下的审批请求、工具调用事件流，能不能满足工作台展示计划和轨迹的需要。
  • MCP 客户端遇到跳转时，会不会把身份请求头带到别的主机。
  • Harness 实际调用 DeepSeek 的哪几个接口（模型网关要按这些接口透传，包括流式返回）。
