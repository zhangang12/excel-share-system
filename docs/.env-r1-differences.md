# 环境差异与配置来源调查报告

## 1. 配置优先级链条

```
┌──────────────────────────────────────────────────────────────────────┐
│                        最高优先（运行时覆盖）                          │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │  DB: app_settings 表（kv）                                      │  │
│  │  · gate_enabled / intranet_cidrs / device_gate_enabled          │  │
│  │  · device_ids                                                   │  │
│  │  · agent_llm.base_url / .api_key / .model / .models             │  │
│  │  · agent_llm.model_fast / .thinking                             │  │
│  │  · agent_briefing_users（未来）                                   │  │
│  │  修改入口：管理页面（admin/manager）；立刻全局生效，不重启         │  │
│  └────────────────────────────────────────────────────────────────┘  │
│                              ↑ 覆盖                                   │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │  环境变量（docker-compose 注入）                                  │  │
│  │  · 开发：${VAR:-default} 语法，默认值写在 compose 文件里           │  │
│  │  · 生产：${VAR} 无默认值（多数），由 .env.prod 文件提供            │  │
│  │  · docker compose -f ... --env-file .env.prod up -d              │  │
│  │  · 生产只暴露 8 个变量给容器（见下方差异表）                        │  │
│  └────────────────────────────────────────────────────────────────┘  │
│                              ↑ 覆盖                                   │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │  .env 文件（pydantic_settings 读取，env_file=".env"）             │  │
│  │  · 开发本地可直接放此文件；docker-compose 也读同文件作为 env_file   │  │
│  │  · 生产容器内无此文件（配置由环境变量注入）                         │  │
│  └────────────────────────────────────────────────────────────────┘  │
│                              ↑ 覆盖                                   │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │  config.py Settings 类硬编码默认值（最低优先）                     │  │
│  │  · database_url = "sqlite+aiosqlite:///./data/app.db"            │  │
│  │  · secret_key = "demo-secret-key-change-in-prod"                 │  │
│  │  · debug = True                                                  │  │
│  │  · ...（共 18 个配置项，全量见下方）                                │  │
│  └────────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────┘
```

### 两条独立线程的优先级分离

| 配置域 | 优先源头 | 备用源头 | 读取方式 |
|--------|---------|---------|---------|
| **Agent LLM** | DB `app_settings` key=`agent_llm.*` | env/`.env` → `config.py` | `_effective_llm_config()` 每次请求实时查库 |
| **外网闸门** | DB `app_settings` key=`gate_*` | 无（库中无记录用硬编码默认："1"/空名单） | `get_gate_config()` 每次请求实时查库 |
| **业务开关**（sales_order_approval / export_approval_enabled / project_dir_own_only） | 环境变量 / `.env` | `config.py` 默认值 | pydantic_settings 启动时一次性加载 |
| **数据库连接** | 环境变量 `DATABASE_URL` | `config.py` 默认 SQLite | pydantic_settings 启动时一次性加载 |

关键结论：**app_settings 覆盖项（Agent LLM / 闸门）可以运行时热改，不改代码不重启；其余配置改完需重建容器。**

## 4. app_settings 表结构和使用方式

### 4.1 表定义（`backend/app/models.py:1145-1153`）

```python
class AppSetting(Base):
    __tablename__ = "app_settings"
    key: Mapped[str] = mapped_column(String(64), primary_key=True)
    value: Mapped[Optional[str]] = mapped_column(Text)
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now(), onupdate=func.now())
```

极简的 kv 表：主键 key（最长 64 字符）、text value、自动时间戳。由 `Base.metadata.create_all` 自动建表。

### 4.3 读写模式

**读取**（每次请求实时查库，无缓存）：
- 闸门：`gate.py:97-107` → `get_gate_config(db)` → `select(AppSetting).where(key.in_(4个闸门key))`
- Agent LLM：`agent_router.py:1210-1229` → `_effective_llm_config(db)` → `select(AppSetting).where(key.in_(agent_llm.*))`
- 查库结果为空 → 回退到 `config.py` Settings 默认值或硬编码默认值

**写入**（upsert 模式）：
- 闸门：`gate.py:110-126` → `set_gate_config()` → 逐 key `db.get()` 或 `db.add()`
- Agent LLM：`agent_router.py:1350-1361` → `PUT /agent/config` → 逐字段 upsert/delete

### 4.4 API 端点

| 端点 | 方法 | 权限 | 描述 |
|------|------|------|------|
| `/api/admin/gate-config` | GET | admin/manager | 读闸门配置 |
| `/api/admin/gate-config` | PUT | admin/manager | 写闸门配置（立即全局生效） |

## 5. 关键发现汇总

1. **双轨配置**：业务开关（sales_order_approval 等）走 pydantic_settings 静态加载；闸门和 Agent LLM 走 DB 实时读——后者可以热改不重启。
2. **生产 debug=True 未关**：`config.py:19` 默认 `debug=True`，生产未显式覆盖。
3. **Docker Compose 差异大**：开发 compose 全用 `${VAR:-default}` 可零配置启动；生产 compose 对 `POSTGRES_USER/PASSWORD/DB` 和 `SECRET_KEY` 无 fallback，缺 .env.prod 必炸。
4. **.env.prod.example 比 .env.example 多 2 个关键项**：`FILES_DIR`（决定上传文件持久化）和 `SALES_ORDER_APPROVAL`（决定销售下单是否需审批）。生产默认开启审批，开发默认关闭。
5. **app_settings 无 schema 约束**：存什么 key 完全由代码约定，没有枚举或校验——`agent_llm.thinking=on` 这种字符串拼写错误只有运行时才暴露。
6. **Agent LLM 配置的安全措施**：api_key 永不回传明文（打码 `****xxxx`），PUT 时传 `-` 可清除库中覆盖值回退 .env 默认，日志只记字段名不记值。
