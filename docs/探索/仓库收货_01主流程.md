## 1 概览：路由归属与角色

收货**没有独立 router**，所有端点定义在 `purchase_mgmt_router.py:20` 的 `APIRouter(prefix="/api/purchase-mgmt", tags=["采购管理"])` 中，并在 `main.py:184` 通过 `include_router` 挂载。

**角色约定**（`purchase_mgmt_router.py:23-28`）：

| 常量 | 角色 | 用途 |
|------|------|------|
| `_RECEIVE_ROLES` | `warehouse`, `warehouse_lead` | 收货读写——仓库专有 |
| `_PURCHASE_ROLES` | `buyer`, `purchase` | 采购基础查询 |
| `_WRITE_ROLES` | `buyer`, `buyer_lead`, `purchase` | 采购创建/编辑 |

`require_roles` 对 admin/manager 自动放行。**采购员只下单不收货**，收货归仓库角色。

## 2 收货端点清单

全部在 `purchase_mgmt_router.py`，调用方均需 `_RECEIVE_ROLES`（或 admin/manager 自动放行）。

### 2.1 `GET /receiving` → `list_receiving`（:1881-1957）

**response_model** = `List[PurchaseItemOut]`

**入参（Query）**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `supplier_id` | int | - | 按供应商过滤 |
| `po_no` | str | - | 采购单号 |
| `keyword` | str | - | #330 采购单号+项目编号模糊（后端过滤，穿透 limit） |
| `item_name` | str | - | #330 物料名模糊 |
| `order_month` | str | - | #330 下单月份，格式 YYYY-MM |
| `received` | bool | `false` | false=待收货(arrival_date IS NULL)，true=已收货 |
| `limit` | int | `2000` | ge=1, le=5000（常量定义在 :1877-1878） |

**逻辑要点**：

- 排序：`po_no DESC NULLSLAST, id DESC`
- `received=false` 时追加 `arrival_date IS NULL` 条件
- **keyword 三分支模糊搜索**（:1909-1916）：
  1. `po_no.ilike(f"%{keyword}%")`
  2. `project_code.ilike(f"%{keyword}%")`
  3. `source_sheet_id IN (Datasheet JOIN Project WHERE Project.code.ilike)` —— 回溯 #253 那批在 `purchase_items` 里 `project_code` 为空的明细
- **#253 回溯补 project_code**（:1924-1946）：对 `project_code IS NULL AND source_sheet_id IS NOT NULL` 且 row 非 None 的行，从 sheet 反查 project、回写到 `pi.project_code`
- **附件计数**：返回 `receipt_count`，来源为 `biz_type="receipt_doc"` 附件数（:1947-1957）

### 2.2 `GET /receiving/meta` → `receiving_meta`（:1960-1989）

**出参**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `pending_count` | int | 待收货总数（真实 count，不受 limit 影响） |
| `received_count` | int | 已收货总数 |
| `pending_suppliers` | list | 待收货全量供应商下拉 |
| `received_suppliers` | list | 已收货全量供应商下拉 |
| `limit` | int | 当前 limit 值 |

前端 `WarehouseView.vue` 的 `loadBadgeCounts` 调用此端点，用于收货页签的徽标数字和供应商筛选下拉。

### 2.3 `PUT /items/{iid}/receive` → `receive_item`（:2013-2046）

单条收货。入参 `PurchaseReceiveIn`（见 3.1 节 schema），业务逻辑：
1. 查 PurchaseItem，校验存在且 `arrival_date IS NULL`
2. 更新 item 字段（arrival_date, received_amount, receiver_sign, warehouse_loc, delivery_note_no 等）
3. 调用 `_finish_receive`（:2040）完成后续

### 2.4 `POST /items/receive-batch` → `receive_batch`（:2049-2107）

合并收货。入参 `BatchReceiveIn`（见 3.1 节 schema），业务逻辑：
1. 循环逐行处理 `BatchReceiveLine`
2. 校验每行 item 存在且未收货
3. 更新每行 item 字段
4. 共用 `_finish_receive`（:2103）

### 2.5 `POST /items/{iid}/receipt` → `upload_receipt`（:2111-2127）

上传收货单附件（图片/PDF）。存 `biz_type="receipt_doc", biz_id=iid`，底层走 `attachments_router.py` 的 `save_upload`。

### 2.6 `GET /items/{iid}/receipts` → `list_receipts`（:2130-2145）

收货单附件列表。查询 `Attachment` 表 `biz_type="receipt_doc" AND biz_id=iid`。

### 2.7 `GET /orders/{po_no}/pdf` → `download_order_pdf`（:595 起）

采购单 PDF。收货页查看/打印用，非收货专属但收货页签直接调用。

## 3 内部函数链（service 层）

全部在 `purchase_mgmt_router.py` 内，无独立 service 文件。

### 3.1 `_finish_receive`（:1992-2010）

收货收尾公共函数，单条和批量共用。执行顺序：
1. 写 `arrival_date`、`delivery_note_no`、`receiver_sign`、`warehouse_loc` 等到 PurchaseItem
2. **回写清单**：调用 `_writeback_sheet_row`（:864-893）写 `_ALL_ARRIVAL_COLS`（到货日期/到料日期）、`_ALL_WH_SIGN_COLS`（仓库签字/仓库）、`_ALL_WH_LOC_COLS`（库位）。若需回写 `project_code` 且非 None 则一并写入
3. **自动入库**：调用 `_auto_stock_in`（:1404-1440）→ 生成 WhTxn(in)
4. **回写流水金额**：调用 `_sync_txn_amount`（:1443-1459）
5. **自动对账**：调用 `_maybe_auto_reconcile`（:724-736）

### 3.2 `_auto_stock_in`（:1404-1440）

- **幂等**：同 `purchase_item_id` 且 `is_reversal==False` 已有 WhTxn 则 return（防止重复入库）
- 按 `name+spec` 找/建 `WhMaterial`
- **单库位模型**：最近收货库位 = 物料当前库位
- 生成 `WhTxn(direction=in, source="采购入库", party=供应商名, project_id=按project_code, ref_no=_next_ref("in",bd))`
- **已取消收货自动出库**：原 `is_stock=False` 自动「采购领用」出库逻辑已删（:1439-1440），出库统一走仓库领料

### 3.3 `_sync_txn_amount`（:1443-1459）

#329 改价后回写已生成入库流水金额。口径：
- 整条一次性入库（`t.qty==item.qty` 且 `received_amount` 非空）→ `amount = received_amount`
- 否则 `qty * unit_price`（合并收货反算单价有分位差）

### 3.4 `_maybe_auto_reconcile`（:724-736）

现金全款/对公全款 + 已收货 + 已付清 → `invoice_status` 自动置「已对账」。
只从「待对账」推进一次，不回退。

### 3.5 `_item_out`（:701-721）

PurchaseItemOut 组装：包含 supplier_name、buyer_name、receipt 相关字段。

### 3.6 `_writeback_sheet_row`（:864-893）

把 `{列名: 值}` 写进清单某行 values。按列名匹配 field_id，列不存在跳过。`only_if_empty` 保留已手填值（#255）。

### 3.7 `_sheet_fieldmap`（:842-844）

构建清单列名到 field_id 的映射。

### 3.8 `_ensure_expected_arrival_field`（:847-861）

缺预计到货列时自动补建。

### 3.9 `_next_ref`

从 `warehouse_router.py:619` 导入，生成入库流水号（格式：IN-YYYYMMDD-NNN）。

## 6 前端调用点

全部在 `frontend/src/views/WarehouseView.vue`（仓库工作台·收货页签），不走 `frontend/src/api/warehouse.ts` 的 `whApi`（whApi 只封装出入库流水/物料/发货清单）。

| 前端方法 | 接口 | 用途 |
|----------|------|------|
| `loadReceiving` | `GET /receiving` | 加载收货列表 |
| `loadBadgeCounts` | `GET /receiving/meta` | 加载徽标计数+供应商下拉 |
| `submitReceive` | `PUT /items/{id}/receive` | 单条收货提交 |
| `submitBatchReceive` | `POST /items/receive-batch` | 合并收货提交 |
| `uploadReceipt` | `POST /items/{id}/receipt` | 上传收货单附件 |
| `viewReceipts` | `GET /items/{id}/receipts` | 查看收货单附件列表 |
| `viewPoPdf` | `GET /orders/{poNo}/pdf` | 查看采购单 PDF |

前端按 `po_no` 分组父行/子行渲染（整单合并收货入口在父行）。合并分组在前端用 `Map(po_no)` 聚合（`groupedRecv`），改价靠 `onRecvCalc`/`onRecvAmountCalc`/`onBatchLinePriceCalc` 双向往返算。收货列表与弹窗用 Element Plus `el-table` 而非项目主用的 `vxe-table`。

## 7 状态流转

```
待收货（arrival_date IS NULL）
    │
    │ PUT /items/{iid}/receive 或 POST /items/receive-batch
    │ → 填 arrival_date + received_amount + 签字/库位/送货单号
    │
    ▼
已收货（arrival_date IS NOT NULL）
    │
    ├── 回写清单：到货日期/仓库签字/库位
    ├── 自动入库：_auto_stock_in → WhTxn(in)
    ├── 回写流水金额：_sync_txn_amount
    └── 自动对账：_maybe_auto_reconcile（现金全款+已收货+已付清）
```

## 8 附件链路

- **上传**：`POST /items/{iid}/receipt` → `purchase_mgmt_router.upload_receipt`(:2111) → `attachments_router.save_upload`（biz_type="receipt_doc", biz_id=iid）
- **列表**：`GET /items/{iid}/receipts` → `purchase_mgmt_router.list_receipts`(:2130) → `Attachment` 表按 biz_type+biz_id 查询
- **下载**：`GET /download/{filename}` → `attachments_router` 的通用下载端点（非收货专属，但 receipt 附件通过此端点获取文件二进制）

## 9 排除项（反例）

- ❌ **不存在独立的 receiving router**：全仓库收货端点都在 `purchase_mgmt_router.py`，前缀 `/api/purchase-mgmt`
- ❌ **收货不在 `warehouse_router.py` 中**：whApi 只封装出入库流水/物料/发货清单，收货交互全在 `WarehouseView.vue` 的收货页签中直接调用
- ❌ **不存在 PurchaseOrder 表**：采购单是纯业务概念，通过 `PurchaseItem.po_no` 字段聚合
- ❌ **出库不经过收货自动领用**：原 `is_stock=False` 的自动领用逻辑已删除，出库统一走仓库领料
