# 仓库收货 · 权限与可见性

> 探索节点 n7 产出。主题：仓库收货模块的权限与可见性——角色读写边界、行级数据隔离谓词唯一真源、菜单门控、跨域读数据隔离。代码位置以 `backend/app` 与 `frontend/src` 为准（2026-08-09 当前 HEAD）。

## 0. 一句话结论

收货的读写边界按「模块域」而非「数据表」划分：**收货动作只归仓库（warehouse / warehouse_lead）**，采购员只下单不收货；采购明细列表按采购角色 + `_buyer_restricted` 行级隔离，但收货清单 `/receiving` **完全不套 `_buyer_restricted`**（仓库看全部采购员的单）；仓库域大量只读接口在接口层只验登录（`get_current_user`），域隔离完全靠前端菜单 `User.menus` + `hidden_tabs`。

## 1. 各角色可见性矩阵

> 依据：`require_roles` 依赖工厂（`backend/app/deps.py:52-62`）——多角色并集，**admin/manager 恒放行**；`has_role` 走 `role_codes`（`backend/app/models.py:79-101`），其中 `finance_lead` 自动并入 `finance`（models.py:85-88）。

| 能力 / 接口 | warehouse | warehouse_lead | buyer 家族（buyer/standard/outsource） | buyer_lead | finance / finance_lead | admin / manager |
|---|---|---|---|---|---|---|
| 查看待收货清单 `GET /receiving` | ✅ 全部明细 | ✅ | ❌ 403 | ❌ | ❌ | ✅ |
| 收货动作（逐条/批量/上传送货单）`PUT /items/{iid}/receive` 等 | ✅ | ✅ | ❌ | ❌ | ❌ | ✅ |
| 收货单附件上传 `POST /items/{iid}/receipt` | ✅ | ✅ | ❌ | ❌ | ❌ | ✅ |
| 收货单附件列表 `GET /items/{iid}/receipts` | ✅ 全部 | ✅ | ⚠️ 仅**自己**明细的（`_buyer_restricted` 命中→403 他人） | ✅ 全部 | ✅ 全部 | ✅ |
| 采购明细列表 `GET /items` | ❌ 403 | ❌ | ⚠️ 仅自己下的单 | ✅ 全部 | ✅ 全部 | ✅ |
| 供应商列表 `GET /suppliers` | ❌ | ❌ | ⚠️ 仅自己新增的 | ✅ 全部 | ✅ 全部 | ✅ |
| 采购明细写操作（增改删/开票/导入/改价）`_WRITE_ROLES` | ❌ | ❌ | ✅ | ✅ | ❌ | ✅ |
| 采购单打印 `GET /po-items/print` | ✅（显式追加） | ✅ | ✅ | ✅ | ✅ | ✅ |
| 请购单 `_PREQ_WAREHOUSE`（新建/认领） | ✅ | ✅ | 仅查看 `_PREQ_VIEW` | ✅ 查看+处置 | 查看 | ✅ |
| 收付款/请款/对账（`require_roles("finance")`） | ❌ | ❌ | ❌ | ❌ | ✅（含 finance_lead 隐含） | ✅ |
| 库存物料/流水/汇总读 `GET /materials`、`/txns`、`/summary`、`/po-items` | ✅ | ✅ | ✅ **任何登录用户** | ✅ | ✅ | ✅ |
| 库存写（出入库/冲红）`POST /txns` 等 `WRITE_ROLES` | ✅ | ✅ | ❌ | ❌ | ❌ | ✅ |
| 库存金额 `/inventory-value`、项目成本 `/project-cost` | ❌ | ❌ | ❌ | ❌ | ✅ | ✅ |
| 字段配置（物料字段/库存字段） | ❌ | ✅（`_WH_FIELD_ADMIN_ROLES`） | ❌ | ❌ | ❌ | ✅ |

关键差异点：
- **仓库能看到比采购员自己更多的采购数据**：`/receiving` 对所有 `_RECEIVE_ROLES` 返回全量明细（不套 `_buyer_restricted`），而采购员自己的 `GET /items` 被 `buyer_id == current.id` 收窄。同一张 `PurchaseItem` 表、两套谓词（见 §2.1）。
- **收货数据不进采购菜单**：`/receiving` 在 purchase_mgmt_router 里，但角色是仓库域；采购员即使有 `purchase_mgmt` 菜单也拿不到收货清单。

## 2. 行级数据隔离谓词唯一真源

### 2.1 `_buyer_restricted`（采购行级隔离，唯一真源）
`backend/app/routers/purchase_mgmt_router.py:46-53`
```
return current.has_role("buyer","buyer_standard","buyer_outsource") and not current.has_role("buyer_lead","admin","manager")
```
- 语义：**只要是采购下单角色且不是主管/管理层** → 只看自己下的单。
- **兼任 finance / logistics / sales 不解除隔离**（注释原文：王芹=buyer/finance/logistics 曾因带 finance 而被判为看全部）。判定只看"是不是 buyer 家族 + 是否 buyer_lead/admin/manager"。
- 纯 finance（不带 buyer）→ False → 看全部对账。
- 调用方（全部复用此函数，禁止在别处重写角色判断）：
  - `list_items`（purchase_mgmt_router.py:380-381）`buyer_id == current.id`
  - `list_suppliers`（:75-76）`created_by == current.id`
  - `batch_invoice`（:2159-2160）收窄到本人明细
  - `list_receipts`（:2137-2141）本人明细的收货单附件，他人 403
  - `set_invoice_no`（:2218 附近）同口径
  - agent 助手 `_scope_po`（agent_router.py:75-79）——与 /items 同口径（见 §5.1）

### 2.2 `_allowed_sheet_keys` + `BUYER_SHEET_MAP`（采购员清单下单范围）
`backend/app/routers/purchase_mgmt_router.py:35-39`，映射本体在 `backend/app/dept_config.py` 的 `BUYER_SHEET_MAP`（仅三名采购员各管自己的清单；其余采购员+采购主管+admin/manager 不受限，返回 None=看全部）。与 `_buyer_restricted` 正交：一个是**可见性**（看哪些明细），一个是**下单范围**（能下哪些清单）。

### 2.3 项目侧行级谓词（非收货路径，作对照）
- `restricted_dir_pids`（`backend/app/deps.py:95-122`）：项目目录/一览行级可见性。`_DIR_RESTRICTED_CODES = {designer,electrician,assembler,sheetmetal,sealing,sales}`（deps.py:92），且开关 `project_dir_own_only` 开才生效；只要兼任任一 `_lead`/admin/manager 即 restricted=False。**收货走采购明细，不经过此谓词**。
- `user_can_view_project`（`backend/app/deps.py:125-146`）：项目详情/字段/导出每项目门禁；admin/manager/任一 `_lead` 全可见，其余按 ProjectMember 成员资格。

## 3. 角色读写边界（角色集合常量）

`backend/app/routers/purchase_mgmt_router.py:22-28`：
- `_PURCHASE_ROLES = (buyer, buyer_lead, finance, finance_lead, buyer_standard, buyer_outsource)` —— 采购读接口（供应商、明细列表、对账、打印）。
- `_WRITE_ROLES = (buyer, buyer_lead, buyer_standard, buyer_outsource)` —— 采购写接口（新增/编辑/删除明细、供应商、开票、导入、改价）。
- `_RECEIVE_ROLES = (warehouse, warehouse_lead)` —— **收货归仓库，采购只下单不收货**。
- `_FIELD_ADMIN_ROLES = (buyer_lead,)`（:906）—— 采购字段配置仅采购主管。
- `require_roles("finance")`（:2607/2664/2682/2702/2763/2826）—— 收付款/请款/对账仅财务（`finance_lead` 因 models.py:87 隐含并入）。

`backend/app/routers/warehouse_router.py`：
- `_WH_FIELD_ADMIN_ROLES = ("warehouse_lead",)`（:26）—— 库存字段配置仅仓库主管。
- `WRITE_ROLES = ("warehouse","warehouse_lead")`（:27-28）—— 出入库/冲红/盘活等写操作。
- `_can_manage_wh(u)`（:30-31）= WRITE_ROLES + admin/manager —— 前端按钮级。
- **读接口大量只挂 `Depends(get_current_user)`**：`/materials`（:124 注释"全员可读=查库存集成点；写操作另校验"）、`/txns`、`/summary`、`/locations`、`/po-items`（:971-989，出库按采购单选料，只返回已到货行）—— 接口层只验登录，域隔离靠前端菜单。
- `/inventory-value`、`/project-cost`（:1317/1340）→ `require_roles("finance","finance_lead")` —— 库存金额/项目成本仅财务。

`backend/app/routers/purchase_mgmt_router.py:3094-3098`：
- `_PREQ_WAREHOUSE` = 仓库+设计+电工+生产+装配/钣金/封板组（请购单新建/处置，:3187）
- `_PREQ_VIEW` = `_PREQ_WAREHOUSE` + 采购/财务（查看，:3129/3167/3323）

## 4. 菜单门控（域级可见性唯一权威）

- **唯一权威** = `user_menu_keys(user)`（`backend/app/menus.py:142-154`）：admin/manager → 全量 `_ALL_KEYS + _ADMIN_KEYS`；其余 → `User.menus`（NULL → `DEFAULT_ACCOUNT_MENUS = ["catalog","list","messages","oa"]`，menus.py:56-58）；无条件追加 `"agent"`。
- `ROLE_DEFAULT_MENUS`（menus.py:64-93）**仅建号预填/迁移模板，运行时不读**：
  - `warehouse` / `warehouse_lead` → `["catalog","list","warehouse"]`
  - `buyer` / `buyer_lead` → `["catalog","list","purchase_mgmt"]`
  - `finance` / `finance_lead` → `["catalog","list","finance","purchase_mgmt"]`
  - `admin` → 全量
- 二级 tab 门控 = `User.hidden_tabs`（`menu_key:tab_name` 映射）：`TAB_REGISTRY`（menus.py:105-135）中 warehouse 菜单含 `("recv", "采购收货")`、`("storage", "库存")` 等。前端 `tv(name)`（WarehouseView.vue:29-32）据此显隐；后端 `get /auth/menus`（auth_router.py:138-146）下发 `hidden_tabs`。
- 登录响应即下发菜单 key 与 hidden_tabs（auth_router.py:23-40 `UserOut`）；前端 `MainLayout.vue` 按 `auth.hasMenu(key)` 渲染一级菜单（:185-189），`WarehouseView.vue` 是唯一落地页（:4 `WAREHOUSE_MENU`）。

## 5. 跨域读数据隔离

### 5.1 AI 助手（agent_router）—— 只读 SELECT，按菜单门控 + 复用页面谓词
- `_allowed_tools(user)`（agent_router.py:567-600）：`keys = set(menus.user_menu_keys(user))`；
  - `purchase_mgmt` 菜单 → po 系列工具（`po_arrival_overdue`/`po_arriving`/`po_overdue_by_supplier`）+ `get_supplier`
  - `warehouse` 菜单 → `get_material`
  - `finance`/`sales` → 台账/应收/对账工具
- 行级：po 工具用 `_scope_po`（agent_router.py:75-79）复用 `_buyer_restricted` —— 与页面 `GET /items` 同口径（配套测试 `backend/tests/test_agent_row_level_scope.py` 断言 AI==页面）。
- 无权限 → `_deny`（agent_router.py:562-564）返回错误不进异常链。
- 铁律（AGENTS.md）：所有数据工具只读 SELECT，不提供收货/付款等强职责命令。

### 5.2 其它跨域读
- `GET /po-items/print`（采购单打印，purchase_mgmt_router.py:598）显式追加 `warehouse, warehouse_lead` —— 仓库可跨域读采购单。
- `GET /po-items`（warehouse_router.py:971，出库登记选料）任何登录用户可读采购已到货行 —— 接口层无采购角色校验，靠前端（仓库菜单内）隔离。
- downstream 推送（downstream_router.py:147/291/376）`require_roles("buyer",... ,"finance_lead")` —— 不涉及仓库。
- notify.py:47-48 `finance_lead ⊇ finance` 隐含同样作用于推送扇出。

## 6. 反例与坑（已排除/待注意）

- **兼任财务不解除采购隔离**：`_buyer_restricted` 只判 buyer 家族，王芹=buyer/finance/logistics 案例（purchase_mgmt_router.py:47-50 注释）。**新增任何跨域读代码必须 import 本体，禁止重写**。
- **`/receiving` 不套 `_buyer_restricted`**：warehouse 角色能看到所有采购员下的单（含单价/金额数据，见 §1 矩阵）。业务定位是"仓库执行收货需要全量"，但与 `GET /items` 的 buyer 隔离形成同一张表两套谓词——若未来要求"仓库按项目/区域收窄"，改动点在 `list_receiving` 的 stmt 构造（purchase_mgmt_router.py:1894-1921），当前无任何行级收窄。
- **"前端隐藏 ≠ 接口隔离"**：`/receiving` 与 `GET /items` 返回的 `PurchaseItemOut` 含单价/总价/供应商全字段（schemas），WarehouseView 用 `isManager`（:19-20 `hasRole('admin','manager')`）隐藏单价/总价列，但**接口层对 warehouse 角色全量返回**——仓库角色可经 curl 直接拿到价格。设计上是显式选择（仓库需改价），记录不追责。
- **仓库域只读接口接口层零角色校验**（§3）：域隔离完全依赖 `User.menus` + `hidden_tabs`。若某账号被管理员误配 `warehouse` 菜单或 hidden_tabs 未收敛，可直接读到库存/流水/采购已到货行。
- **`/receiving` 里 `_RECV_LIMIT_DEFAULT`**（:1889，limit 默认值）为 2000（#330 后），`GET /receiving/meta`（:1960）出真实 `count(*)` —— 页面数字是 count 而非返回行数。
