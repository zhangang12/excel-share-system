# n12 · 核实#2·证伪：收货自动入库是单库位模型

**判决：PASS（说法成立）**

## 说法回顾

> 收货自动入库是单库位模型：同一物料（name+spec 匹配）被多次收货到不同库位时，`_auto_stock_in` 就地覆盖 `wh_materials.location` 为最近一次库位，且 `_stock_map` 实时库存不按库位区分；做多库位/库位盘点相关需求前需先评估此模型。

## 逐项证实

### 1. `_auto_stock_in` 确实覆盖 `WhMaterial.location`

**证据**：`backend/app/routers/purchase_mgmt_router.py:1423-1424`

```python
elif loc:
    m.location = loc   # 🆕 库位管理：最近一次收货放到哪,物料当前库位就是哪(单库位模型)
```

- 1418 行：物料不存在时，新建 WhMaterial 以当前库位为 location
- 1423 行：物料已存在且本次有库位时，**直接覆盖** `m.location = loc`
- 代码注释明确标注"单库位模型"

**行为确认**：假设物料"轴承座 SKF-6205"第一次收货到"A区-1排"，`WhMaterial.location = "A区-1排"`；第二次收货到"B区-3排"，location 被覆盖为"B区-3排"，"A区-1排"信息在物料主数据层面丢失。

### 2. `_stock_map` 实时库存不按库位区分

**证据**：`backend/app/routers/warehouse_router.py:34-55`

```python
async def _stock_map(db: AsyncSession, material_ids: Optional[list[int]] = None,
                     upto: Optional[str] = None) -> dict[int, float]:
    """各物料实时库存 = init + Σin − Σout（可选 upto=YYYY-MM-DD 含当日，用于期初/期末）。"""
    q = select(models.WhTxn.material_id, models.WhTxn.direction, func.sum(models.WhTxn.qty))
    # ...
    q = q.group_by(models.WhTxn.material_id, models.WhTxn.direction)
```

- GROUP BY 维度：`material_id` + `direction`（in/out）
- **没有** `location` 维度
- 返回类型：`dict[int, float]`，即 `material_id → 库存数量`
- 无法回答"某个物料在 A 库位有多少、在 B 库位有多少"

### 3. `WhMaterial` 模型只有一个 `location` 字段

**证据**：`backend/app/models.py:384-402`

```python
class WhMaterial(Base):
    __tablename__ = "wh_materials"
    # ...
    location: Mapped[Optional[str]] = mapped_column(String(64))          # 库位（单仓仅文本）
```

- 只有一个 `location` 字段，`String(64)` 标量
- 没有物料-库位多对多关联表
- 没有 `locations` 列表字段（JSON 数组等）

### 4. 独立的 WhLocation 表只做库位主数据管理

**证据**：`backend/app/models.py:745-754`

```python
class WhLocation(Base):
    """🆕 库位主数据（仓库维护）：采购下单选库位、出入库流水记库位都从这里取值。
    单库位模型：一个物料一个当前库位(WhMaterial.location)，流水记录每笔的实际库位。"""
    __tablename__ = "wh_locations"
```

- `WhLocation` 只是库位字典表（name + note + sort_order）
- 不做物料-库位关联
- 注释明确承认"单库位模型"

### 5. 手工出入库也有同样的覆盖行为

**证据**：`backend/app/routers/warehouse_router.py:780-785`

```python
if data.direction == "in":
    txn_loc = loc or m.location
    if loc:
        m.location = loc
else:
    txn_loc = m.location
```

手工入库填库位时同样会覆盖 `WhMaterial.location`，行为一致。

### 6. 流水表 WhTxn 保留历史库位记录（但实时库存不利用）

**证据**：`backend/app/models.py:416`

```python
# WhTxn
location: Mapped[Optional[str]] = mapped_column(String(64))         # 🆕 库位(入=放到哪/出=从哪领)
```

流水表有独立的 `location`，记录每笔出入库的库位。但这不改变实时库存层面是单库位的事实——`_stock_map` 不使用这个字段做分组。

## 影响评估

- **同日多次收货不同库位**：后入的库位覆盖先入的，先入库位信息在主数据层丢失（只能在流水表追溯）
- **库存查询**：`GET /warehouse/list` 显示的库存是一个物料的总计，不区分库位
- **出库**：领料时默认从 `WhMaterial.location`（当前库位）出，不与流水表记录的历史库位对比
- **库位盘点**：没有库位级别的库存对账能力——系统不知道"A区-1排 应该有多少库存"，只知道"轴承座总共 50 个，当前库位 B区"
- **库存总览按库位过滤**：`GET /warehouse/list` 支持 `?location=xxx` 参数（`warehouse_router.py:119`），但筛的是物料主数据的当前库位（`wh_materials.location`），不是流水的库位（`wh_txns.location`），语义是"哪些物料的当前库位是 xxx"而非"哪些物料在 xxx 库位有库存"（因为实时计量的 `_stock_map` 根本不区分库位，理论上可能存在物料 location 指向 A 库位但实际所有 in 流水都在 B 库位的情况）

## 证伪尝试与结论

本卡的默认立场是"这条是错的"。尝试从以下角度证伪：
1. 查找物料-库位多对多关联表：**不存在**。全模型搜索 `wh_material` + `location` 无关联表。
2. 查找 `_stock_map` 有 location 维度的替代实现：**不存在**。唯一版本即按 material_id 聚合。
3. 查找 WhMaterial 有多个 location 字段：**不存在**。只有一个 `location` 列。

证伪失败，说法经逐一核实后成立。
