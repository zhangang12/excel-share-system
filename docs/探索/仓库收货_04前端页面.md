# 仓库收货 · 前端页面探索（04/前端）

> 系列：「仓库收货的逻辑」。本文探索 **frontend 端**收货相关页面与组件：收货单列表、收货录入/逐条维护、合并收货、筛选框、列宽、改价交互、图片/附件上传。每个交互的 API 端点、数据流、可编辑字段、前端过滤逻辑、代码位置。后端契约与数据流见系列其它篇（后端 purchase_mgmt_router 端点已在本文件每节标注对应位置）。
> 结论全部来自直接读码，证据为 `frontend/src/views/WarehouseView.vue:行号`。

## 0. 一句话结论

前端收货交互**全部**在单个文件 `frontend/src/views/WarehouseView.vue`（2054 行）内实现，**没有独立组件、没有独立 API 模块**——收货相关的 HTTP 调用全走 `http` 直调（不走 `frontend/src/api/warehouse.ts` 的 `whApi`）。该文件同时承载仓库模块全部 6 个 tab（库存总览 / 出入库流水 / 物料需求 / 采购收货 / 发货清单 / 采购申请），收货只是其中一个 tab pane。表格用的是 **Element Plus `el-table`**（非项目主用的 vxe-table）。附件预览复用通用组件 `frontend/src/components/AttachmentPreview.vue`。

## 1. 入口与权限门

- 入口：`WarehouseView.vue:1381` `<el-tab-pane v-if="tv('recv')" name="recv">`，tab 标签带待收货角标（`recvPendingCount`，1382）。
- tab 可见性 = 账号菜单驱动：`tv(name) = auth.tabVisible('warehouse', name)`（20 行），与 AGENTS.md「菜单唯一权威 = User.menus」一致。
- 操作权限 = 角色驱动：`canWrite = auth.hasRole('warehouse','warehouse_lead','admin','manager')`（18 行）。非仓库角色进 tab 只见 `EmptyHint`「仅仓库角色可确认收货」（1383 行），整块操作区（筛选框+表格+按钮）不渲染。
- 切进 tab 触发加载：`onTab('recv') → loadReceiving() + loadRecvMeta()`（810 行）。

## 3. 数据流总览（状态 → 接口）

```text
onTab('recv')
  ├─ loadReceiving()  GET /purchase-mgmt/receiving            → recvItems（待/已按 received 分流）
  └─ loadRecvMeta()   GET /purchase-mgmt/receiving/meta       → recvMeta（条数/供应商下拉/limit）
groupedRecv = merge(recvItems)  → 树形渲染
用户交互 →
  单条收货/修改   PUT    /purchase-mgmt/items/{id}/receive
  合并收货/修改   POST   /purchase-mgmt/items/receive-batch
  上传收货单      POST   /purchase-mgmt/items/{itemId}/receipt   (FormData)
  看收货单        GET    /purchase-mgmt/items/{itemId}/receipts  → AttachmentPreview
  采购单 PDF      GET    /purchase-mgmt/orders/{poNo}/pdf        (blob 新标签)
```

## 4. 每个交互的 API 端点与代码位置

### 4.1 列表加载 `GET /purchase-mgmt/receiving`
- `loadReceiving()`（WarehouseView.vue:451-466）。前端把 4 个筛选控件的值塞成 query 参数：
  ```ts
  { received: recvReceived, supplier_id, keyword: recvPo.trim(), item_name: recvName.trim(), order_month: recvOrderMonth }
  ```
- 后端：`purchase_mgmt_router.py:1881`（`response_model=List[PurchaseItemOut]`）。**#330 起三个搜索框全部走后端**（keyword 匹配采购单号/项目编号、item_name 物料名、order_month 下单月份），可搜到 limit 上限之外的老单。
- 返回行带收货联动字段：`unit_price`（可为 null = 后填）、`received_amount`、`delivery_note_no`、`arrival_date`、`stock_location`、`project_code`、`receipt_count`、`po_no`、`delivery_date`、`notes`（#356 备注列数据源）。

### 4.2 元信息 `GET /purchase-mgmt/receiving/meta`
- `loadRecvMeta()`（468-475）。返回 `{ pending_count, received_count, pending_suppliers, received_suppliers, limit }`，驱动：
  - tab 角标 `recvPendingCount` / `recvDoneCount`（computed，376-383）；
  - 供应商下拉全量 `recvSupplierOptions`（384-389，按 `recvReceived` 切 pending/received 供应商列表，#310 可搜索）；
  - 截断告警文案（`recvTruncated` computed，397-399，`recvItems.length >= limit`）。
- 后端：`purchase_mgmt_router.py:1960`（真实 `count(*)` 与全量供应商，#330）。

### 4.3 单条收货/修改弹窗（1912-1960）
- 打开：`openReceive(row)`（500-513）→ 预填表单后 `recvVisible=true`。
- 提交：`submitReceive()`（546-564）
  ```ts
  PUT /purchase-mgmt/items/{recvForm.id}/receive
  body: { delivery_note_no, arrival_date, unit_price, received_amount, stock_location, project_code }
  ```
- 后端：`purchase_mgmt_router.py:2013`。
- **可编辑字段**（弹窗内）：送货单号、到货日期（必填）、库位（必填，#204 收货时统一填，同步采购明细/装配/钣金/设计/电工）、订单编号（选项目或直接输，allow-create，#253 手工单补编号）、单价、收货金额（#346 可填负数——优惠券负金额行）、收货单附件（选填）。
- 收货成功后 `loadReceiving(); loadBadgeCounts(); refreshAfterReceive()`（563-564）。`refreshAfterReceive`（540-545）补刷 materials / txns / demand / demandOverview——库存、流水、物料需求一次到位，不用等重进页面（#291）。

### 4.4 合并收货/合并修改弹窗（1963-2010）
- 两种打开方式：
  - `openBatchReceive()`（606-620）：表格勾选多行（`recvSelected`，`recvItemIds` 数组）→ 合并这些跨单零件。
  - `openBatchReceiveGroup(row)`（621-638）：合并父行整批收货，直接取 `row.children`。
  - 两处都会把父行/子行的 `delivery_note_no / arrival_date / stock_location / project_code` 预填（「多个」合并值按 `!= '多个'` 取第一个，#321/#253）。
- 提交：`submitBatchReceive()`（639-660）
  ```ts
  POST /purchase-mgmt/items/receive-batch
  body: {
    item_ids: [...],                          // 顶层也带，兼容旧契约
    delivery_note_no, arrival_date, stock_location, project_code,
    lines: [{ item_id, unit_price, received_amount }]
  }
  ```
- 后端：`purchase_mgmt_router.py:2049`。
- 弹窗内**逐行可编辑**：单价、收货金额（el-input-number，1993-1998）。填单价自动按数量算金额（`onBatchLinePriceCalc`，见 §5.2）。收货单附件整批共用一份。
- 提交后同样 `loadReceiving(); loadBadgeCounts(); refreshAfterReceive()`（668）。

### 4.5 图片/附件上传（收货单）
- `uploadReceipt(itemId, file)`（532-535）：`FormData('file', file)` → `POST /purchase-mgmt/items/{itemId}/receipt`（后端 2111）。
- 单条：`pickRecvReceipt`（526-531）隐藏 input 选文件 → 存 `recvReceiptFile`，提交时随 `submitReceive` 一起上传（558-561）。
- 合并：`pickBatchReceipt`（595-600）→ `batchReceiptFile`，提交后对每行 `uploadReceipt(l.item_id, batchReceiptFile)`（663-665）——**一份收货单图片上传到该批次每条 item 上**。
- 查看：`viewReceipts(row)`（578-584）→ `GET /items/{iid}/receipts`（后端 2130）取附件列表，最近一张走 `AttachmentPreview.open({id, name})` 预览（783）。`AttachmentPreview` 组件位置 `frontend/src/components/AttachmentPreview.vue`（2013 行挂载，582 行展示列表）。

### 4.6 采购单 PDF
- `viewPoPdf(poNo)`（567-576）：`GET /purchase-mgmt/orders/{poNo}/pdf`，取 blob → 新标签打开。入口：采购单号列（1422）、操作列固定「采购单」按钮（1484）。

## 5. 改价交互与前端计算

### 5.1 单条弹窗（1919-1949）
- `onRecvCalc`（514-518）：填**单价** → `received_amount = unit_price × qty`。
- `onRecvAmountCalc`（519-523）：填**收货金额** → `unit_price = received_amount / qty`。
- 两个 `el-input-number` 均 `:controls="false" :precision="2"`，可互为反算；#346 允许负数。

### 5.2 合并弹窗（1986-1998）
- `onBatchLinePriceCalc(row)`（601-605）：填某行单价 → 该行 `received_amount = unit_price × qty`，金额仍可手动改。
- `#308`：弹窗打开即对**金额为空**的行按预填单价补算一轮（617、635 行），已填金额不动。

### 5.3 历史「合并总价分摊」已清理（2026-08-09）
- `#1` 已删掉「合并总价按数量分摊」模式（`batchRecvMode` 只剩 'lines'）。
- 旧残留 `splitShare()`（按数量分摊函数）、`batchRecvForm.total_amount`、`batchTotalQty` computed 与 `batchRecvMode` 状态（只赋值无读取）**已于本次清理**，`vue-tsc -b` 通过。`submitBatchReceive` 请求体本就只含 `lines` 逐行价（639-652）。

## 6. 前端过滤 / 合并分组逻辑

### 6.1 前端过滤 `filteredRecv`（391-399）
三重**前端过滤**（在 recvItems 上即时收窄，配合后端搜索提供边打字边缩小的即时反馈）：
```ts
recvPo.trim()    → po_no / project_code 含匹配
recvName.trim()  → item_name 含匹配
recvOrderMonth   → delivery_date.startsWith(month)
```
注意：前端月份过滤基于 **delivery_date（下单时间列）**，与后端 `order_month` 参数**同口径**——`purchase_mgmt_router.py:1920` 同样按 `PurchaseItem.delivery_date.startswith(month)` 过滤。三组搜索框前端过滤只是「边打字边缩小」的即时反馈，点查询/回车后走后端全库搜索（keyword 还带 `source_sheet_id IN (...)` 分支回溯 #253 老单，见 1906-1916）。

### 6.2 合并分组 `groupedRecv`（406-450）
- 按 **po_no** 分组（`Map<po_no, 行[]>`），po_no 为空的单行单组直接平铺。
- 组内 ≥2 行 → 生成父行：`_isGroup=true, _count=N, children=[...]`；qty/received_amount/receipt_count 聚合求和；`delivery_note_no / arrival_date / stock_location / project_code / delivery_date` 全行一致才带值，否则显示「多个」/「—」（406-440）。
- `recvRowKey`（403）：`row._isGroup ? 'g'+row.po_no : 'i'+row.id`（树 key 稳定）。
- `grpRowClass`（405）：父行加 CSS 类，前端有 `grp-row` 样式强调合并行。

## 7. 其它关联点

- tab 徽标：`recvPendingCount/recvDoneCount` computed 取 recvMeta（376-383）；`loadBadgeCounts()`（481）同时刷全局角标。
- 全局刷新：页面顶部 `PageRefresh` 组件（14 行 import，反馈 #359 每页有刷新），刷新即重挂载本 tab。
- 项目下拉：`loadProjects()`（776-780）复用 `GET /projects` 取仓库有详单权限的项目，供订单编号选择（弹窗 1936-1939 / 1981-1984）。
- 库位下拉：`enabledLocations`（77 行）取 `locations.filter(l => l.enabled)`，数据来自 `whApi` 的库位接口（弹窗 1930-1932）。

## 8. 反例 / 已排除路径

- **收货不在采购页面**：采购管理视图（`frontend/src/views/PurchaseMgmtView.vue`）不含收货交互；grep 全前端 `receive-batch|/receiving|/receive` 除本文件外仅命中销售/物流的 `receiver`（收货人地址，与仓库收货无关）。
- **不走 vxe-table**：仓库模块收货列表与弹窗明细用的都是 Element Plus `el-table`；项目其它模块主用 vxe-table，此处是历史实现，未迁移。
- **不经过 `frontend/src/api/warehouse.ts`**：收货 6 个端点全部 `http.get/post/put` 直调（`frontend/src/api/index.ts` 的 axios 实例），`whApi` 只封了出入库流水 / 物料 / 发货清单 / 采购申请（仓库其它功能），收货没有走它——改动接口时别在 whApi 里找收货。
