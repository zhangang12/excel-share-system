# n17 · 核实#3 证伪结果：前端 isManager 价格隐藏 vs 接口全量返回

> 核实员 · 证伪视角 | 判决: **PASS**（说法成立）

## 被核说法

> 前端用 isManager 隐藏单价/总价列，但 GET /receiving 和 GET /items 的响应 PurchaseItemOut 对 warehouse/buyer 角色全量返回单价金额字段，接口层无价格级隐藏，curl 可直接拿价格（设计上仓库需改价故有意为之，记录不追责）

## 核实过程与证据

### 1. isManager 的定义与使用范围

**定义**：`frontend/src/views/WarehouseView.vue:19`
```
const isManager = computed(() => auth.hasRole('admin', 'manager'))   // #5：单价/总价仅管理层可见
```

**使用方**（仅 4 处，全在 WarehouseView.vue）：

| 行号 | 用途 | 上下文 |
|---|---|---|
| `:1067` | 库存总价 KPI | `<div v-if="isManager" class="kpi">` — 库存总览 tab 的总价值指标卡 |
| `:1116-1118` | 物料单价列 | `<el-table-column v-if="isManager" label="单价">` — 库存物料表 `:data="materials"` |
| `:1119-1121` | 物料总价列 | `<el-table-column v-if="isManager" label="总价">` — 同上，库存物料表 |

**结论**：`isManager` 只控制**库存物料表**（materials tab）的单价/总价可见性，**不涉及收货清单**（receiving tab）。

## 判决：PASS

**核心说法成立**——理由：

1. 接口层确实无价格级角色隐藏：`/receiving` 返回 `PurchaseItemOut` 全量价格字段，`/items`（``:380-381``，`_buyer_restricted` 行级但无字段级）同理
2. `isManager` 是前端唯一的价格隐藏手段，但**它只控制库存物料表的列，不控制收货清单的列**——这意味着仓库角色在前端收货清单中就能直接看到价格，无需 curl。自证的最有说服力的反例：`WarehouseView.vue:1448-1456` 收货清单的价格列无 `v-if` 约束。
3. 设计意图（仓库需改价）与代码一致：收货清单提示语"单价未填的（后填价格）在此补上"（`:1398`），收货弹窗提供 `onRecvCalc`/`onRecvAmountCalc` 改价逻辑（`:514-521`）

### 说法中唯一可修正的细微表述

"前端用 isManager 隐藏单价/总价列"应更精确地表述为"前端用 isManager 隐藏**库存物料表**的单价/总价列，但收货清单中的价格列对所有仓库角色完全可见"。这不影响说法的核心结论（接口层无价格级隐藏），只是前端的隐藏程度比说法暗示的更窄。
