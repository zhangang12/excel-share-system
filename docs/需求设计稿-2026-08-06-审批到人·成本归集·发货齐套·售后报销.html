审批配到人、费用归到成本、发货看客户、售后自带报销

这四条是你提的，逐条问过口径、已经定完，本稿转为开发依据。 每节最后一块绿框就是定下来的结论。
做的顺序：① 审批到人 → ④ 售后自带报销 ＋ ② 费用归成本（捆在一起）； ③ 发货资料暂缓——查生产库发现光免掉铭牌说明书解决不了问题，见那一节。

① 审批链指定到人 ② 费用按部门归成本 ③ 发货资料看客户分类 ④ 售后登记自带报销 上线顺序
OA 审批

审批链能指定到具体某个人

「能不能具体到某个人，不要按照部门配置审批流程。比如我挂的部门比较多， 有销售部、财务部、采购部，不能具体到某个人审批。」

现在

一条审批链的每一步存的是角色，不是人：

oa_approval_steps (department_id, doc_type, step_order) → approver_role

1. 售后部主管→ 2. 财务主管→ 3. 财务部

轮到某一步时，凡是挂着这个角色的人都能批。你挂了销售部＋财务部＋采购部， 于是很多本该别人批的单子也会落到你待办里。

改成

每一步二选一：按角色（保留，适合"谁在岗谁批"）或指定到人。

approver_role 旁边加一个 approver_user_id， 配置界面那一行从「选角色」变成「选角色 / 选人」两个下拉。

1. 售后部主管→ 2. 张三（指定）→ 3. 财务部

在途的单子不受影响——现在的设计就是提交那一刻把审批链快照下来， 改配置只影响新提交的单，这条不用动。

指定到人，就必须先想好这个人不在的时候怎么办。 配成角色时谁在岗谁批，天然不会卡；配成具体的人，一旦他休假、出差、离职， 单子就停在那一步不动了。这是这条改动唯一真正的风险，不解决会变成新的堵点。

已定

✓
指定的人不在时：设代理人，本人 3 天没处理就自动同时进代理人待办 本人仍然能批。比"自动跳过"安全，比"死等"顺畅。代理人跟指定到人同批发布， 不然指定到人就成了新堵点。
✓
先只做「一步指定一个人」，会签以后再说 按角色配的老方式保留不动，两种配法共存：这一步要么选角色、要么选人。
✓
挂多部门走错链的问题：不用改，现在就已经解决了 查过代码，提交申请时本来就要选以哪个部门的名义提 （create_request 从请求体取 department_id）， 不是按人所在部门瞎猜。
成本归集

OA 里的费用按部门统计到对应成本

「0A 审批里面的费用能不能根据部门做统计，售后部提交的报销统计到售后成本里面， 销售部提交的统计到销售成本里面。」

现在

OA 申请单 oa_requests 上已经有部门、申请金额、 财务核定金额，但这些钱不进任何成本口径——审批完就停在 OA 里， 财务想看某个部门花了多少，只能自己翻单子。

改成

建一张「部门 → 成本科目」的对照表，报销类单据审批通过后自动落到对应成本：

提交部门计入
销售部销售成本
售后部售后成本 （见第 ④ 节，会重复）
生产部 / 电工部 / 设计部制造费用
人事行政 / 财务部管理费用

对照表做成可维护的，以后加部门不用改代码。

金额要用财务核定的那个数，不是申请的数。 单据上申请金额和 settle_amount（财务核定）是两个字段， 经常对不上。成本必须按核定金额算，否则报出来的部门成本天然虚高， 老板看到的数跟财务账对不上。

已定

✓
审批通过就计入成本，另给财务一列「是否已付」 成本看得早，同时看得见哪些批了还没付。两头都不耽误。
✓
金额一律按「财务核定金额」算 settle_amount 为空时才回退用申请金额。 按申请金额算的话，财务扣过款的单子成本会虚高，老板看的数跟财务账对不上。
✓
OA 的采购申请不计成本，成本一律以采购单为准 OA 采购申请只当审批用。否则同一笔钱在 OA 和采购单里各算一次，直接翻倍。
✓
差旅按提交人所在部门归集 跟这一节"按部门统计"的口径一致。唯一例外是售后／安装的差旅—— 那部分跟着售后单走，见第 ④ 节。
发货闸门

发货资料按客户分类判定，经销商不卡铭牌说明书

「铭牌、说明书、电路图、送货单必须齐了后才能确认发货，但有些经销商的单子没有铭牌说明书， 那就没办法确认发货了。能不能根据销售下单的客户分类，经销商只需要电路图、送货单， 终端客户就正常。」

现在（我查过代码，口径跟你描述的不完全一样）

发货闸门实际判的是：这个项目所有已下单、未作废的部门任务，必须全部完成 （logistics_router._d5_gate）。

铭牌和说明书是设计部那张任务单的产出，电路图是电工部的产出。 资料没传齐→部门任务不敢点完成→整个项目卡在"待齐"，发不了货。

所以卡住经销商单子的不是一张"资料清单"，是部门任务完不成。这决定了改法。

改成

销售下单时给单子标客户类型，闸门按类型取不同的必需资料：

客户类型发货前必须齐不卡
终端客户铭牌 · 说明书 · 电路图 · 送货单—
经销商电路图 · 送货单铭牌 · 说明书

被免掉的资料仍然可以传，只是不再拦着发货；设计部那张单也能正常点完成。

已定

✓
不新建字段——销售下单时的「客户分类」就是它 销售台账上早就有 cust_type，取值就是 经销商／终端客户， 而且只有这两类。生产上已经填得很整齐：终端客户 67、经销商 59，只有 2 条空的。 直接拿来用，不再造第二个字段。
✓
存量数据不用刷，按现有的客户分类走 数据本来就是准的，没有"默认成哪一类"的问题。
⏸ 这一条暂缓 查生产库时发现跟设想的不一样：97 个未发货项目里，卡住的是生产部 53 单、电工部 37 单， 设计部只卡了 1 单——而铭牌／说明书是设计部的产出。也就是说光免掉铭牌说明书， 现在这批经销商的单还是发不了。等你确认物流那边到底是被什么拦住的，再动这一条。
售后 · 与第 ② 节绑定

售后／安装登记时直接报销，不再走 OA

「他们售后报销都是选择售后部走 0A 申请。如果 0A 里的售后报销统计到售后成本， 那跟售后部登记售后的费用就重复了。我的想法是登记的时候直接可以申请走报销了…… 描述售后问题解决办法以后，下面就是费用清单报销模块，可以添加行、插入对应的发票， 然后提交申请，最终到财务部。售后主管审批之后直接到财务出纳， 出纳核对报销明细发票无误后安排报销。」

你说的重复是真的，而且现在就已经在发生。 售后登记表 aftersales 上有一个 cost 字段， 售后主管审批后同步财务；同一笔钱，售后的人又在 OA 里按"售后部 / 费用报销"报了一遍。 第 ② 节一旦把 OA 按部门归集，这笔钱就会在"售后成本"里出现两次。 所以 ② 和 ④ 必须一起上线。

现在：两条路，都通向售后成本

售后登记→ 售后主管审批→ 同步财务部
OA · 售后部 · 费用报销→ 售后部主管→ 财务主管→ 财务部

登记时只能填一个总额加一份物料清单附件，发票没地方放， 出纳核对时还得回去找人要。

改成：只剩一条路

售后／安装登记（含费用清单＋发票）→ 售后主管审批→ 财务出纳 · 核对发票→ 安排报销

登记表单从「选项目 → 填问题 → 填费用 → 传清单」变成：

  • 选项目 · 描述问题与解决办法
  • 费用清单（可加行）：每行 费用项 · 金额 · 发票附件 · 备注
  • 总额由明细自动合计，不再手填——手填就会跟发票对不上

数据上新增 aftersales_items 明细表， 原来的 cost 单值字段改为明细合计。

配套动作（不做这条，重复就消不掉）： OA 的「部门＝售后部」下把费用报销 / 差旅费用报销这两个单据类型停掉， 入口处直接提示「售后和安装的费用请在售后部登记里提交」。

已定

✓
售后／安装的差旅费跟这单售后一起报 费用清单里加一行「差旅」即可。能算进这个项目的售后成本，也不会跟 OA 重复。
✓
核对发票这一步用现有的「财务部」角色，不新建出纳角色 改动最小，财务部的人都能核对报销。
✓
已经在 OA 里在途的售后报销单，照原路走完 新单一律走新路。中途搬家容易把单子搞丢，也会让当事人不知道该去哪看。
✓
发票对不上就退回登记人重传，改完直接回到财务部这一步 谁传错谁改，不用售后主管再批一遍。
