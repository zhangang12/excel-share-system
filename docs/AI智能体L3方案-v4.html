同辉智能体 L3 重构方案

做一个通用的 L3 智能体：用户在系统里能查的、能做的，它都能查、能做；给它一个目标，它自己规划步骤、调用系统能力、核对结果，在权限和沙箱里干活，只在关键节点找人确认。

本稿取代 2026-08-01 版的第四、五节，以及本方案的 v1–v3。8 月版的三条核心原则继续有效：只走业务接口同一条路径；事实以服务端为准；能力可枚举。v4 写入了 8 条拍板结果（第 15 节），并按 Harness 安全审计 改了运行时的设计（第 08 节）。

00先回答：L3 智能体不是 SOP

SOP / 流程自动化L3 智能体（本方案）
谁定步骤人事先写死，机器照做给目标，智能体自己规划，人可以改计划
能做哪些事只有写过流程的那几件用户在系统里能做的，都能做
遇到没见过的情况卡住，等人改流程换路、查数、问人
安全靠什么流程本身沙箱演练、权限、审批模式、撤销
SOP 在哪SOP 就是系统本身SOP 只是它能查阅的知识，帮它做得更稳

v2 犯的错，是把「挑几个业务流程做成技能」当成了智能体本身，结果更像流程自动化。v3 改成以通用能力为主线。业务场景只出现在两处：评测考题（第 11 节），用来衡量能力到没到 L3；开放顺序（第 12 节），决定先给谁用。它们不决定架构，也不限制智能体能做什么。

v2 里验证过的结论都保留：零改造演练、事件触发、影子运行、渐进授权、DeepSeek Harness 的定位。

要改的两条旧红线

  1. 「工具永远只读」改为「写操作只走登记过的接口，先演练、再按审批模式执行」。智能体没有自己的高权限账号，永远以发起人身份执行。AGENTS.md 第 70 行同步改。
  2. 「不做多 Agent」改为「主 Agent + 按需子 Agent」。子 Agent 继承发起人身份，权限不能更大；每次运行有轮次、时间、费用上限。

03对标 Codex

Codex 的核心不是写死了哪些开发流程，而是给模型一套通用工具（读写文件、跑命令），让它能做开发者能做的任何事；安全靠沙箱和审批模式，而不是少给工具。我们照这个思路做。

04通用行动：接口即工具

用户在网页上能做的每件事，背后都是一个接口。智能体以用户本人的身份调用同一个接口，就能做同一件事，而且权限、校验、审计都和网页完全一样，不用另写一套。

要解决的几件事

  • 工具自动生成：名称、说明、参数格式都从接口文档里来，新增接口自动出现。
  • 接口文档要补：开放范围内的接口，请求体字段 533 个一个说明都没有，路径和查询参数 687 个只有 32 个有说明，说明文字中位数 34 字。自动生成前先加一层中文「工具说明补充」，按使用频率优先（最高频的是改项目详单单元格、仓库批量出库、改采购明细）。
  • 工具太多：给模型一份 34 个模块的目录，用到哪个模块再加载它的工具；按用户的菜单权限先过滤一遍。
  • 结果太大：列表接口可能一次返回几千行（采购明细 3,799 行）。全量留在服务端，只给模型统计摘要、前几行和可用的筛选条件。
  • 敏感字段（已拍板）：银行账号、身份证号、工资薪酬、手机号，发给模型前在 ERP 侧打码。模型拿到的是代号，需要把号码填到别处时，由服务端换回真值；用户看到的明细不受影响。
  • 上传文件（已拍板开放）：附件都经同一个保存函数落盘，演练时记下新写的文件，回滚后删除。
  • 写接口白名单：每个开放的写接口登记一行：风险等级、能不能撤销、撤销调哪个接口。没登记的不开放。
  • 复合工具保留：现有手写的分析工具（资金面板、毛利、交期看板等）保留，一次给出跨表结论；通用接口负责长尾。

05安全执行：沙箱、审批模式、渐进授权

  • 演练：写接口原样运行在外层事务里，内部的提交只落到保存点，跑完整体回滚；企微和站内通知只有一个出口，演练时截下不发。拿到逐字段改动，生成变更预览卡。
  • 确认时重演：人点确认的那一刻再演练一次，和预览不一致（比如别人刚改过）就让人重新确认。
  • 风险等级：R0 只读 · R1 可逆草稿 · R2 业务写 · R3 钱、审批、删除、对外。按接口所属模块和路径自动初判，再人工复核一遍。
  • 审批模式（按人 × 动作类设定，管理员给每个角色定上限）：只读：不能写；建议（默认）：每个写操作都出预览，人点确认才执行；自动：只对挣得授权的动作类，执行后出日报，留撤销窗口。R3 永远停在「建议」。
  • 撤销与熔断：可逆的写操作登记对应的撤销接口；每人每天写操作数量、金额都有上限，异常率高了自动降回「建议」。
  • 审计：每条写操作记两个人：谁发起（智能体代谁）、谁确认。
第 1 级 · 影子只演练，不给人看对真实事件出方案并演练，和人实际的做法逐条比对。达标才升级。
第 2 级 · 建议出预览，人点确认人改了哪些字段都记下来，作为纠错样本。
第 3 级 · 自动挣来的，可收回某人对某类动作连续确认 20 次、零修改、零撤销，才可改为自动。一次撤销或投诉就退回第 2 级。

06规划、执行、核对

  • 计划卡：复杂任务先列步骤给人看，人可以改、删、加步骤。例：「把 2026-092 的收货信息补全，然后安排发货」→ 查项目 → 查同客户历史收货人 → 填收货人（预览）→ 查发货闸门 → 通知物流。
  • 执行：逐步执行，只读步骤可以并行；每个写步骤都走演练和审批模式。
  • 核对：每步执行完回读数据，确认改动真的生效、没有多改别的；不通过就停下报告，能撤的自动撤回。
  • 挂起与恢复：等审批、等到货时挂起，事件到了自动接着做；任务状态存在后端，过几天也能接上。
  • 限额：每个任务的步数、时长、费用都有上限；最后一轮只许总结（10-01 已上线的做法）。

07主动性：事件与盯守

  • 事件来源：在网关层，给每个成功的写请求发一条事件（哪个接口、谁做的、改了哪个对象），不用改业务代码；再加上定时扫描（已有逾期提醒、晨报）。
  • 两类订阅：系统规则，比如「请款提交 → 预审」「到货 → 起草物料档案」；个人盯守，比如「盯着 2026-092 直到发货，每天告诉我卡在哪」「有人改了收款账号马上告诉我」。
  • 任务队列：事件转成任务，由持锁的 worker 执行（先复用现有定时任务的文件锁，之后拆成独立容器）；有超时、重试、死信，每条规则可一键停用。

08运行时：Harness 管思考，ERP 管动手和刹车

已拍板用 DeepSeek Harness 当生产运行时。安全审计 的结论是：默认配置不能上生产（5 项严重、7 项高），但风险项都是独立插件，能逐个关掉。按加固清单改造后可以用，前提是安全边界放在 ERP 这一侧。

flowchart LR
  U[用户：网页 · 桌面 · APP · 企微] --> FE[我们的前端：智能体工作台]
  FE --> BE[ERP 后端：登录 · 会话存储 · 审批卡片 · 分流]
  BE -->|简单查询| FAST[现有快速通道：直答 · 卡片 · 晨报]
  BE -->|多步任务| SV[会话管家：每人一个进程 · 最多 2 个 · 空闲回收]
  SV -->|标准输入输出| HA[Harness 进程 · 用户甲]
  SV -->|标准输入输出| HB[Harness 进程 · 用户乙]
  HA -->|推理| GW[模型网关：记账 · 月度上限 · 剥离多余字段]
  HB -->|推理| GW
  GW --> DS[DeepSeek API]
  HA -->|MCP · 本人令牌| MCP[ERP MCP 服务：工具 · 打码 · 演练 · 审批校验]

  MCP --> API[原业务接口] --> DB[(PostgreSQL)]
谁负责负责什么
Harness思考：多步规划、调用工具、上下文管理与压缩、执行轨迹。只保留和 ERP 通信的那一个通道，命令行、文件、上网、脚本、子 Agent、遥测、会话日志上传等插件全部禁用（审计第 05 节 B 项）。
erp-gate 插件（自建）Harness 内的第一道闸：白名单守卫只允许 ERP 工具；写工具一律转人工审批。
会话管家每个活跃用户一个 Harness 进程，带本人令牌；同时最多 2 个，其余排队；空闲 15 分钟回收；对话历史存在我们后端，新会话带摘要续接（Harness 不能恢复会话）。
模型网关Harness 不直连 DeepSeek：逐次记账、月度上限 1000 元（临时）、只转发推理必需字段；API Key 只在后端。
ERP MCP 服务第二道闸，也是真正的保证：按令牌识别用户，以本人身份调原业务接口；写操作必须有后端签发的审批记录（调用编号 + 参数哈希）才执行；演练、打码、限额、审计都在这里。
ERP 后端分流只有 2 个并发名额，所以简单查询、确认卡片、晨报继续走现有的快速通道，只有多步任务才交给 Harness。

Harness 是预览版，官方说明会有破坏性变更。所以我们 fork 一份、固定版本；升级前必须先过业务评测、越权回放和加固自检。

按需求里列的顺序，对应到上面的设计。标了 v4 的是这一版因 Harness 当运行时改过的。

M1

工具

做什么
接口工具从接口文档自动生成（读 120、写 212），先补中文说明；复合分析工具保留；按模块目录按需加载；大结果留服务端只给摘要；四类敏感字段打码。全部经 ERP MCP 服务提供给 Harness。
验收
新接口上线后自动可用；工具选错率在评测里可量。
M2

ERP MCP 连接器v4

做什么
从第四阶段提前到第一阶段：它是 Harness 和 ERP 之间唯一的通道。按每用户令牌鉴权；不返回说明文字、固定工具清单、不发跳转、限制返回大小、校验资源 URI（防审计里的提示注入面）；写操作核对审批记录。之后再对外开放给其他智能体。
验收
以采购员身份接入，查到的和网页一字不差；没有审批记录的写调用一律被拒；越权回放 0。
M3

SKILL

做什么
经验包，不是流程边界：常做的事写成技能，命中时给模型参考。Harness 自带的技能插件会读文件系统，审计建议禁用；技能改由 ERP MCP 以只读资源的形式提供，由我们管理、审核、版本化。
验收
有技能和没技能时，同一题的步数和成功率对比可量。
M4

多 Agent 架构v4

做什么
Harness 自带的子 Agent 首期禁用：审计发现它继承父级全部工具，还会在后台无人值守地续跑。阶段三再评估两条路：限定只读工具、前台模式后重新开启；或由会话管家拉起受限的独立进程（受 2 个并发名额约束）。
验收
重新开启前，越权回放证明子 Agent 调不到写工具。
M5

沙箱v4

做什么
真正的沙箱在 ERP 侧：演练事务（已验证，零改造，含上传文件）、确认时重演、影子库。Harness 自带的沙箱只管写文件、不隔离网络，不依赖它；Harness 跑在隔离容器里：不发布端口、只能访问我们自己的后端、根文件系统只读、非 root。
验收
每个开放的写接口：演练改动 = 真实执行改动；演练零外发；容器内无法访问公网。
M6

权限管理v4

做什么
两道闸：Harness 内 erp-gate（白名单 + 写操作转审批）；ERP MCP 服务（令牌识别本人、白名单与风险等级、审批记录核对、职责分离与金额阈值、打码、熔断）。审批模式默认「建议」，连续确认 20 次、零修改零撤销才可转自动，R3 永远要确认（已拍板）。
验收
越权回放 0；拔掉 erp-gate 后写操作仍全部被 ERP 拒绝。
M7

网关分流v4

做什么
两个网关：业务入口在 ERP 后端（鉴权、配额、并发闸、把简单查询分给快速通道、多步任务交给 Harness）；模型网关在 Harness 与 DeepSeek 之间（记账、月度上限 1000 元、剥离多余字段、熔断）。
验收
能答出「这个月花了多少钱、花在谁身上、花在哪类任务上」；到上限自动降级。
M8

主 Agent 路由v4

做什么
ERP 后端先判断：简单查询直接答（现有快速通道，不占并发名额）；要动手的多步任务交给 Harness；事件任务按规则派发。Harness 内部的规划由它自己完成。
验收
分流准确率 ≥ 90%；Harness 并发名额不被简单查询占用。
M9

多 Agent 协同

做什么
人机协作先行：把某一步转交给人、等某人确认、会签，都在 ERP 的任务板上。Agent 之间的协同等 M4 评估后再上。
验收
转交给人的步骤有人接、有结果，全程可追溯。
M10

数据埋点

做什么
两处汇总：Harness 的执行轨迹（经会话管家收集）+ ERP 侧的工具调用、审批、演练、执行、撤销、费用。正式记录以 ERP 为准；Harness 落盘的会话日志 7 天清理。
验收
任何一次运行都能完整回看；周报自动生成。
M11

自学习工程

做什么
不训练模型，学工具说明、技能、组织知识和样例：评测驱动改进；影子比对；人改过的预览存成纠错样本；从成功轨迹总结技能（人审核）；反复被追问的口径由智能体提议入库。
验收
走通一次「失败 → 改进 → 评测通过 → 上线」。
M12

Loop 工程v4

做什么
内循环由 Harness 负责（规划、调用、观察）。Harness 自带的无人值守续跑、后台任务唤醒首期禁用（审计中危项）；事件触发和定时任务放在 ERP 侧的任务队列里，需要智能体时由会话管家开一个受审批约束的会话。
验收
事件到智能体开始处理 < 1 分钟（有空闲名额时）；没有任何写操作在无人确认时执行。
M13

上下文工程

做什么
Harness 负责单次会话内的上下文组装与压缩；我们负责跨会话：对话历史和任务进度存在 ERP 后端，新会话带摘要续接；组织知识（口径、SOP、数据字典）经 MCP 资源提供。
验收
进程回收、换设备后，任务能接着做。

11评测基准：业务场景用在这里

Codex 的能力是在真实代码任务上量出来的。我们的能力，也要在真实业务任务上量。这就是业务场景在 L3 方案里的位置：当考题，不当流程。

档位题型来源怎么判分
L1 查询单接口能答的问题近 30 天 206 条真实提问答案对不对
L2 分析多接口汇总、判断真实提问 + 各部门补题结论和关键数字对不对
L3 行动多步、含写操作审计日志里的真实操作（把「某人做了什么」倒推成任务，他做完后的数据就是标准答案）在影子库里跑，看数据终态是否一致；同时记步数、耗时、费用、越权次数

首批试点场景（用来验证通用能力，不单独开发）：请款预审、仓库建档与出库、采购对账。选它们是因为近 60 天这三块的手工操作占了 55%。每次发版都跑全量题库，分数不退步才放行。

14风险与对策

风险对策
Harness 本身不安全（官方说明未经安全审计，不得用于生产）按审计加固清单关掉执行能力和外发；隔离容器不出公网；安全边界放在 ERP 侧，Harness 被攻破也执行不了未审批的写操作
Harness 预览版破坏性变更fork 并固定版本；升级前过业务评测、越权回放、加固自检
只有 2 个并发名额简单查询不占名额；多步任务排队并告知预计等待；空闲 15 分钟回收；跑满一个月看排队数据再定是否加机器
通用写能力误操作白名单；先演练；默认建议模式；自动要渐进授权挣得；R3 永远确认；熔断；可撤销
提示注入（ERP 备注、上传文档里夹带指令）MCP 不返回说明文字；写操作必须人工确认且 ERP 核对审批记录；前端只渲染同源图片
工具太多、接口说明太少，模型调错先补中文工具说明；模块目录按需加载；评测里量选错率
演练占锁、预览后数据变了演练设几秒超时、只演练单个对象；确认时重演
模型费用模型网关逐次记账，月度上限 1000 元（临时），到上限自动降级；一个月后按实际调
一线不用工作台 + 企微推送，不靠聊天框；开放范围随能力扩大，每阶段有试点人

15拍板结果

#事项结果（2026-10-01）
1定位做通用 L3 智能体，不做 SOP 流程自动化
2「工具永远只读」红线改：写操作只走登记过的接口，先演练、再按审批模式执行；同步改 AGENTS.md

6DeepSeek Harness直接当生产运行时；先做安全审计（已完成），按加固清单适配现有系统

前端复用的考虑

你要求前端页面重构和复用。Harness 自带的前端是 React 写的单人控制台，带终端和插件安装，要运行它的网页服务才能用。审计建议：复用它的交互设计和事件模型（会话、计划、执行轨迹、审批），也复用我们现有智能体页面的组件，在我们的 Vue 前端里重构成「智能体工作台」；Harness 自带网页只给我们自己内网排障用。详见审计报告第 07 节。
